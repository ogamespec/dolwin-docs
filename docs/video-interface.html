Video Interface (VI)

VI is the block inside the Flipper ASIC that reads the external framebuffer (XFB) out of main memory and turns it into a serial video stream for the display. It generates all the NTSC / PAL / M-PAL timing an external encoder needs and, in the retail design, is entirely digital — an external Rohm encoder turns that stream into the TV signal.

This is the register-level, emulator-focused specification. The facts are drawn from the repository's hardware documentation and reverse-engineering sources and summarised rather than reproduced verbatim. It describes the legacy (GameCube) VI as sold.

1. Overview

The VI is a scan-out engine. On every line it issues cache-line reads to the memory controller, unpacks 4:2:2 YUV data, optionally runs it through a horizontal resampling / anti-aliasing filter, and clocks the result out on a digital bus together with generated sync/blanking flags. A vertical counter and a horizontal (pixel) counter produce the line / field / frame timing.

The three-component pixel path is:

main RAM (YUV 4:2:2) ──vi_mem_read──▶ vi_hscaler ──▶ vi_hf (FIR) ──▶ vi_rohm ──▶ vdata / vphase

2. External interfaces

2.1 PI / VI register interface

Registers are reached through the Processor Interface. The bus is asynchronous to the video clock and sampled on both ends (so a request and its acknowledge are never on the same cycle). All register data is 16-bit; a 32-bit CPU access is split by the PI into two 16-bit transfers (high word at the base, low word at base+1), and the whole Flipper is big-endian.

2.2 VI / encoder interface (VI/EN)

The digital output to the video encoder is a 10-pin interface at 27 MHz (the pixel-clock domain), doubling to 54 MHz only for progressive ("480p") output.

PinWidthDescription
vclk1Video clock (27 MHz, 54 MHz in progressive)
vphase1Phase — low selects the YCb set, high the YCr set
vdata8YCrCb pixels during active display; timing flags during blanking

The stream carries Y, Cb, Cr at the 4:2:2 rate. During blanking the two chroma bytes are reused to transmit the timing flags, so the encoder must reconstruct them to the full line rate — meaning HSYNC and the colour burst can be shifted by one pixel. Two cases matter for the encoder and for emulators modelling pixel timing:

  • HBE even — the first chroma sample of the active line is Cb.
  • HBE odd — the first chroma sample is Cr.

2.3 VI / memory interface (VI/MEM)

The VI is a bus master on the main-memory interface. All reads are cache-line sized (32 bytes) and return over the 64-bit data bus in four back-to-back clocks.

SignalDescription
vi_memAddr[28:5]Cache-line aligned address of the read
vi_memReqOne-cycle request to enqueue a read
mem_viAckOne-cycle acknowledge; first 8 bytes return on this cycle
mem_viData[63:0]64-bit data; a cache line arrives across 4 clocks
mem_viReqFullEnhanced mode only — inhibit further requests while asserted

In legacy (GameCube) mode the VI keeps one outstanding read request: a new request is issued only after the previous one is acknowledged, and the picture is always fetched in-order.

3. Addressing and pixel geometry

The VI derives every fetched word from a base pointer plus fields in the picture configuration and base registers. It uses word units where one word is 16 pixels (one 32-byte cache line for 4:2:2 YUV at 2 bytes/pixel).

word_per_line = ceil(picture_width / 16)                     // words per scan line

FBB = picture_origin + x_offset/16 + y_offset * word_per_line   // base (in words)
STD = 2 * word_per_line                                          // picture stride, words
XOF = x_offset % 16                                              // pixel offset in first word
WPL = ceil(XOF + display_width / 16)                             // fetched words per line

STD (stride), WPL (words/line) and XOF let the VI window and pan the displayed region at pixel resolution without copying data in main memory.

3.1 Frame buffer format

The external framebuffer (XFB) is stored as packed YUV 4:2:2 (the "Y1UY2V" layout), four bytes per two pixels:

pixel pair  :  Y0  U0  Y1  V0
byte offset :  +0  +1  +2  +3

Each cache line (32 bytes) holds 16 pixels. Y is clamped to the legal video range, but during blanking Y is forced to zero and the Cb/Cr positions carry the timing/status flags (see §4.3). Cb and Cr are averaged to 4:4:4 before filtering — this lets luma and chroma share control logic and stops a chroma read from running ahead of the luma read.

4. Video timing

The heart of the VI is a timing generator: a vertical line counter and a horizontal pixel counter running continuously at the 27 MHz pixel clock (13.5 MHz luma/chroma sample rate). Their outputs are decoded by a programmable decoder that implements one of four modes — NTSC, PAL, M-PAL and a debug mode (a reduced-size format for bring-up and simulation).

Vertical parameters are in half lines, except ACV which is in full lines and is double-buffered (it changes at the start of the vertical back porch, giving software a full vblank interval to update the mode).

The vertical counter runs on a frame basis (interlace) or a field basis (non-interlace). It is a frame line count — on a 525-line NTSC frame, vertical count 264 is the first full line of the second field and 525 is the last line; the four fields are numbered 1–4. In non-interlaced mode the same 1–525 numbering is retained even though only the odd fields are shown.

4.7 Progressive mode

The 525-line progressive (480p) mode uses a 54 MHz video clock (selected by the clock-select register) and produces the same line rate as NTSC (525 lines) or, if programmed for 625, the same as PAL. Non-interlaced fields run at just under 60 fps (263 lines) / just under 50 fps (313 lines). There is no colour burst in progressive mode, so HCS/HCE and BS/BE are left unprogrammed.

7. Horizontal scaler

The scaler lets a small frame buffer be stretched horizontally to the display width. It is a 6-tap resampling filter with eight phases per tap plus a zero tap (49 taps in total).

  • Y, Cb and Cr are buffered in three shift registers; the first and last pixels are replicated at the boundaries so the filter always has a full neighbourhood.
  • A stepper is incremented by the step size for every output pixel. The low 8 bits of the stepper are rounded to 3 bits to select the filter phase; the single bit immediately left of the binary point, when it toggles, shifts a new input pixel into the registers.
  • The datapath is time-shared between the three components (the video clock is twice the pixel rate).
step_size = floor(256 * destination_size / source_size) / 256

The step size and coefficients are programmed through the register interface; the cut-off frequency, pass-band ripple and stop-band attenuation are therefore software-controlled. Because the filter is symmetric, only half the coefficients are stored: the centre 16 in [0,2.0) and the outer 32 in [-0.125,0.125).

Default taps. The system library programs a default 24-tap filter when the VI is initialised (the scaler is left disabled). The un-packed tap values are:

8. Gun-trigger (light-gun) and 3D display

8.1 Gun trigger

Two inputs latch the current beam position. The latch-enable field (LE0/LE1) is double-buffered, so it becomes active on the next field. Three sampling modes exist:

  • one-field — armed for one field, auto-disarms on trigger or time-out;
  • two-field — armed for two fields, same auto-disarm;
  • continuous — armed until explicitly disabled.

Only the first trigger within a field is latched; later triggers in that field are ignored.

8.2 3D display

Two frame buffers (left and right) can be merged into one stream that alternates between the two pictures every two pixels. The left/right base and bottom-base registers hold the second picture pointer; the right picture is unused in 2D mode.

9. Emulator notes

To model the VI in software:

  1. Clock. The VI pixel clock is 27 MHz; the horizontal counter advances every 27 MHz tick (13.5 MHz luma/chroma). In progressive mode the clock is 54 MHz.
  2. Counters. Maintain a horizontal counter (pixels per line, 1-based) and a vertical counter (lines per frame, 1-based, reset at pre-equalisation). Derive HSYNC, HBLANK, colour-burst and the active window from HCS/HCE/HSY/HBE/HBS; derive VSYNC, VBLANK, field/frame number and equalisation/serration from EQU/ACV/PRB/PSB/BS/BE.
  3. Field/frame. The field flag toggles each field; combine interlaced fields with the standard half-line offset. In non-interlace only the odd field is shown, on the same 1..525 basis.
  4. Fetch. Issue 32-byte cache-line reads from the computed FBB with the stride STD; XOF/WPL give the per-line fetch window.
  5. Pixel format. Each cache line is 16 pixels: Y0 U0 Y1 V0 Y2 U1 Y3 V1 … (4 bytes per pixel pair); U/V are the Cb/Cr chroma.
  6. Scaler. When HS_EN is set, resample horizontally with the 6-tap × 8-phase filter using the programmed STP (step) and SRCWIDTH (source count); the default step is 0x100 and the default taps are given above.
  7. Interrupt / retrace. VI_INT_0..3 fire on matched HCT/VCT; any of them also raises the VI master interrupt, which the OS uses as the "retrace" callback. It is cleared by writing a zero to the INT status bit.
