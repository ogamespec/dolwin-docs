Clock Generator

The board's clocking: a single 27 MHz reference oscillator feeding a clock generator that produces the system, CPU, memory, audio and video clock domains — and how this is handled by an emulator.

1. Role

Everything on the board is synchronised to a single low-frequency reference. From it the clock generator derives the domains used by the major subsystems:

DomainFrequencyDriven byUsed by
Reference27 MHz27 MHz crystal oscillatorMaster timebase for the whole board
System / memory bus162 MHzClock generator (PLL)Gekko interface and Flipper
CPU core486 MHzGekko on-die PLL (3 × bus)Gekko core
Audio DSP / ARAM81 MHz½ of the bus clockAudio DSP, ARAM SDRAM
Video27 / 54 MHzClock generator + TV encoderVideo Interface (VI)

Getting these ratios right keeps the CPU speed, the memory bus, the video beam and the audio sample rate mutually consistent. All subsystems are derived from the one 27 MHz reference, so there is a single source of timing truth.

2. Reference oscillator (27 MHz)

The master reference is a 27 MHz crystal oscillator on the main board:

PinDir.Function
CLKO_pOutBuffered 27 MHz output to the clock generator
XIN_pInCrystal terminal; external clock input in bypass
XOUT_pOutCrystal drive terminal (inverted)
STOP_nInActive-low — stop the oscillator (output held low)
BYPASS_nInActive-low — bypass; an external clock is injected on XIN_p
AVDD/AGNDPwrAnalog supply / ground (model-only, unconnected net)
  • Normal: the crystal oscillates; CLKO_p carries 27 MHz and XOUT_p is the inverted drive back to the crystal.
  • Stop: STOP_n low freezes the oscillator and drives the output low (gates the clock while idle or held in reset).
  • Bypass: BYPASS_n low disables the internal crystal and passes an external clock on XIN_p through to CLKO_p — a test notch.

3. Clock generator chip

The clock generator takes the 27 MHz reference and the reset state and produces the system clocks. It is a frequency-synthesis block that multiplies the reference up to the system clock used by the CPU and Flipper:

PinDir.Function
osc_inInReference input from the oscillator
osc_outOutFeedback to the crystal / oscillator
cpuclkOutGekko system clock
flipclkOutFlipper system clock
x54mhzOut54 MHz clock
resetbInActive-low reset
  • The CPU and Flipper are clocked by the same system clock domain — one source drives both. Flipper uses it directly; Gekko multiplies it on die with its own PLL for the core.
  • The 54 MHz output is a separate domain, buffered to the board and fed to the Video Interface (viclkin); the TV encoder independently derives its own 27/54 MHz video clocks and returns them to Flipper's viclk27/viclk54.
  • The chip is reset by resetb (active-low); the oscillator's STOP_n can also hold the clock off.
  • In the chip's RTL model the system-clock period is a parameter, so a tester can override it; the retail design runs the bus at 162 MHz and divides/multiplies to the subsystems (DSP at half the bus clock, video at the 27/54 MHz base).

4. Clock tree and distribution

                 +--------------------+
  27 MHz crystal |  Clock generator   |-- CPU system clock ---> Gekko
   (osc_in/osc_out)|  (PLL, resetb)    |-- Flipper clock   ---> Flipper
                 +--------------------|-- 54 MHz          ---> VI (viclkin)
                          |
                          +-- 27/54 MHz (TV encoder) ---> VI (viclk27/viclk54)

On the CPU PLL path the board also carries a small programmable PLL and a clock buffer/fan-out:

  • The PLL is a general-purpose clock synthesizer with divider straps for the reference (R), output (S) and VCO (V) dividers, plus a power-down/tri-state control.
  • Its output is fanned out (optionally zeroed) by a clock buffer that produces a set of output clocks, gated by a two-bit select.
  • The selected clock reaches the Gekko PLL, whose on-die divider/multiplier (PLL_EXT/PLL_CFG[0:3] straps, plus the CPU PLL connection pins) sets the core-to-bus ratio. See HW/Gekko/PLL_CFG.txt.

Other clock-area nets on the board:

  • Flipper's PLL/reset pins: rstinb, rstswb, lock, byppll, clk, clko — lock reports PLL lock, byppll selects bypass.
  • The memory clocks (memclk/memclkb/memckq) and the ARAM clock (sdclk) are generated by Flipper from its own clock and returned to the memories; the ARAM clock is half the system bus.

5. Reset and PLL behaviour

The clock generator and the rest of the board are held in reset during power-up. A board power-on/watchdog asserts the reset line and releases it after a number of system-clock cycles, so the reference, PLL and memories are stable before the Gekko starts fetching. Asserting reset again re-runs the sequence. PLL lock (reported on Flipper's lock pin) and bypass mode are scan/debug features rather than normal operating states.

6. Emulator application notes

An emulator does not need to model the clock generator silicon; it needs to reproduce the clock domains it produces and the timing ratios between them.

  • Single timebase. Derive every subsystem from one 27 MHz reference. The bus/CPU/DSP/video clocks are integer ratios of it, so one master tick multiplied into each domain keeps them consistent. Avoid independent free-running clocks per subsystem.
  • Video timing. The VI counts horizontal/vertical positions in the 27/54 MHz domain. An accurate beam position (for VBlank interrupts, light-gun latching and the display mode) comes from counting against the video clock relative to the real output resolution and refresh — not a fixed "one line = N ticks" assumption, since the ratio depends on the mode (interlaced, double-strike, progressive).
  • Audio. The AI/DSP sample rate and ARAM DMA are tied to the audio clock tree. For a 32/48 kHz mix, derive the timestamps from the clock ratio rather than a host-time timer, so the streams stay in sync with the video.
  • CPU / bus. Model the 162 MHz bus clock and 486 MHz core (3 × bus). Instruction/memory-access timing and the FIFO/burst behaviour the CPU drives into Flipper depend on the bus clock. Keep the core multiplier (from the PLL_EXT/PLL_CFG and PLL-connection straps) as configuration, not a constant.
  • Determinism and reset. The board re-arms after a fixed number of system-clock cycles in reset. Reprocessing that count (rather than a wall-clock delay) keeps boot and reset reproducible. A cycle-accurate model can reproduce the PLL lock period and clock-stop/bypass test states; a high-level emulator can usually ignore them.
  • Where the models are used directly. The oscillator, clock-generator, PLL and buffer RTL models are what a board-level testbench/FPGA design instantiates for its clocks. A software emulator replicates their output (the domains and ratios) instead of the modules.
